# FR_R0025 RecentCheckDbOrBackupAge

| Field | Value |
|---|---|
| RuleId | `FR_R0025_RecentCheckDbOrBackupAge` |
| Category | Maintenance |
| Severity | Medium |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.4 |
| Lifecycle | Active |
| Data source | `FR_BackupHistory` |
| Dedup anchor | db (D-074) |

## What it detects

A database whose last FULL backup (or CHECKDB) is older than the configured threshold.

## How it is computed

Repository-only (D-014/D-081). Latest FULL backup age vs `BackupWarnDays`; CHECKDB age vs `CheckDbWarnDays` where a signal exists.

## Severity rationale

Medium (High for CHECKDB age).

## Confidence rationale

High — observed from backup history.

## Evidence-type rationale

Observed.

## False-positive risks

Age is limited by repository retention (a very old backup may show '>retention').

## False-negative risks

Databases with no captured backup rows cannot be aged precisely.

## Drill-down guidance

Confirm the backup schedule and chain; consider a FULL backup only after validating RPO. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0025_RecentCheckDbOrBackupAge';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

`BackupWarnDays`, `CheckDbWarnDays`. See [configuration.md](../configuration.md).

## Example

Seed FR_BackupHistory with a stale last-FULL date.
