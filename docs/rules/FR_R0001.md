# FR_R0001 ActiveBlockingChain

| Field | Value |
|---|---|
| RuleId | `FR_R0001_ActiveBlockingChain` |
| Category | Blocking |
| Severity | High |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.1 |
| Lifecycle | Active |
| Data source | `FR_Request` |
| Dedup anchor | lead-blocker `SessionId` (D-074) |

## What it detects

A session at the head of a blocking chain — it blocks others but is not itself blocked.

## How it is computed

Repository-only (D-014/D-081). For each window snapshot, a lead blocker is a `SessionId` that appears as another row's `BlockingSessionId` and is not itself blocked. One finding per distinct lead blocker.

## Severity rationale

High — an active blocking chain is a live, observed contention problem.

## Confidence rationale

High — directly observed from `BlockingSessionId`, not inferred.

## Evidence-type rationale

Observed.

## False-positive risks

A brief, self-resolving block captured in one snapshot still reports.

## False-negative risks

Sub-minute chains between snapshots are missed; only directly-blocking heads are named.

## Drill-down guidance

Inspect the lead blocker's transaction and what it holds; correlate with FR_R0002/FR_R0007. Never kill blindly. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0001_ActiveBlockingChain';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

None. See [configuration.md](../configuration.md).

Seed FR_Request with sessions blocked by a common head (see tests/rules/).
