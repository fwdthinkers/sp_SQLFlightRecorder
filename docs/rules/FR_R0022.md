# FR_R0022 LogReuseWaitElevated

| Field | Value |
|---|---|
| RuleId | `FR_R0022_LogReuseWaitElevated` |
| Category | IO |
| Severity | High |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.4 |
| Lifecycle | Active |
| Data source | `FR_PerfCounter` (Log Growths), `#fr_baseline` |
| Dedup anchor | counter (D-074) |

## What it detects

Transaction-log growth/reuse pressure elevated over baseline.

## How it is computed

Repository-only (D-014/D-081). Window max of 'Log Growths' vs the recent baseline (D-092); downgrades Confidence with <5 samples.

## Severity rationale

High — log pressure can stall writes.

## Confidence rationale

High (Low with insufficient baseline).

## Evidence-type rationale

Observed.

## False-positive risks

A one-off growth from a large transaction can trip it.

## False-negative risks

Requires the perf counter to be captured; sub-minute events averaged.

## Drill-down guidance

Review log backup cadence and long transactions (FR_R0002). Shrinking the log is not a fix. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0022_LogReuseWaitElevated';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

None (baseline via `BaselineLookbackHours`). See [configuration.md](../configuration.md).

## Example

Seed FR_PerfCounter 'Log Growths' rising above baseline.
