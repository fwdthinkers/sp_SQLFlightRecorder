# FR_R0007 BlockingStorm

| Field | Value |
|---|---|
| RuleId | `FR_R0007_BlockingStorm` |
| Category | Blocking |
| Severity | Critical |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.2 |
| Lifecycle | Active |
| Data source | `FR_Request` |
| Dedup anchor | window (D-074); folds FR_R0001/FR_R0002 (§7.13) |

## What it detects

Many sessions blocked within a single snapshot — a blocking storm.

## How it is computed

Repository-only (D-014/D-081). Distinct blocked sessions per snapshot; fires when the peak reaches `BlockingStormSessionThreshold`.

## Severity rationale

Critical — widespread blocking is a severe live incident.

## Confidence rationale

High — directly observed.

## Evidence-type rationale

Observed.

## False-positive risks

A momentary fan-out on one snapshot can trip the threshold.

## False-negative risks

A storm spread across snapshots (not concentrated) may not peak.

## Drill-down guidance

Find the lead blocker; the folded FR_R0001/FR_R0002 contributors are listed in MoreInfo. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0007_BlockingStorm';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

`BlockingStormSessionThreshold` (default 5). See [configuration.md](../configuration.md).

## Example

Seed >=5 sessions blocked by one head in a single snapshot.
