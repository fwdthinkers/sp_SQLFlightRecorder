# FR_R0018 FailedPlanForcing

| Field | Value |
|---|---|
| RuleId | `FR_R0018_FailedPlanForcing` |
| Category | QueryStore |
| Severity | Medium |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.3 |
| Lifecycle | Active |
| Data source | `FR_QueryStoreTopN` |
| Dedup anchor | db+query+plan (D-074, AnchorKey) |

## What it detects

A forced plan reporting force failures (Query Store).

## How it is computed

Repository-only (D-014/D-081). Rows with `ForceFailureCount > 0`, deduped by (db, query, plan).

## Severity rationale

Medium.

## Confidence rationale

High — observed from QS forced-plan columns.

## Evidence-type rationale

Observed.

## False-positive risks

A transient force failure that later succeeds still reports.

## False-negative risks

Only queries in the captured top-N are seen.

## Drill-down guidance

Review why the forced plan fails and whether forcing is still intended; do not force/unforce automatically. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0018_FailedPlanForcing';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

None. See [configuration.md](../configuration.md).

## Example

Seed FR_QueryStoreTopN with IsForcedPlan=1 and ForceFailureCount>0.
