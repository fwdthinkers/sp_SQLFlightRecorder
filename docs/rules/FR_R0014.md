# FR_R0014 AlwaysOnRoleOrStateChange

| Field | Value |
|---|---|
| RuleId | `FR_R0014_AlwaysOnRoleOrStateChange` |
| Category | HA |
| Severity | Critical |
| Confidence | High |
| Evidence type | Observed |
| Introduced in | 0.2 |
| Lifecycle | Active |
| Data source | `FR_AlwaysOnState` |
| Dedup anchor | ag/replica (D-074) |

## What it detects

An Always On replica changed role or synchronization health during the window.

## How it is computed

Repository-only (D-014/D-081). Flags when a replica shows more than one distinct role or health state across the window.

## Severity rationale

Critical — a role/health change is a major HA event.

## Confidence rationale

High — observed.

## Evidence-type rationale

Observed.

## False-positive risks

A brief, expected transition (planned failover) reports.

## False-negative risks

Changes fully contained between snapshots are missed.

## Drill-down guidance

Review the AG dashboard and cluster log for the timeframe. Drill-down queries are read-only (D-086).

## Suppress / disable

```sql
EXEC dbo.sp_SQLFlightRecorder @Mode = N'Configure',
    @ConfigKey = N'DisabledRules', @ConfigValue = N'FR_R0014_AlwaysOnRoleOrStateChange';
```
Suppressed rules are listed in FR_R0026 (D-101).

## Related config keys

None. See [configuration.md](../configuration.md).

## Example

Seed FR_AlwaysOnState with a role/health change across snapshots.
